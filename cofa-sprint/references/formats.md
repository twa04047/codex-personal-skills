# 개발 지도와 상세 spec 양식

기존 프로젝트 양식이 있으면 재사용한다. 다음은 새 프로젝트 또는 사용자가 양식 변경을 요청했을 때의 출발점이다. spec00은 큰 개발 흐름을 간결하게 쓰고 spec01부터는 필요한 만큼 상세화한다. 각 기능에 적용되는 항목을 사용하고, 분량 제한 없이 항목과 예시를 확장할 수 있다.

## spec00.md

```markdown
# 개발 지도
근거: [README.md의 요구사항]
목표: [업무 결과와 성공 지표]
필수: [요구사항의 원문 근거]
선택·제외: [이번 개발에서 선택하거나 제외한 큰 범위와 이유]
미정: [결과를 바꾸는 질문 또는 없음]
공통 보호 기준: [프로젝트에 적용되는 권한·입력·비밀·보존 조건]

| spec | 큰 단계·개발 내용 | 사용자 결과·요구 ID | 선행 단계·공유 계약 | 담당 영역 | 완료 확인 | 모델·추론·fast | 상태 |
| --- | --- | --- | --- | --- | --- | --- | --- |

병렬 가능: [작업 쌍과 조건, 공통 파일 통합 담당]
작업 예산: [사용자가 지정한 시간·비용이 있으면 구현·검증·문서 갱신에 배분]
```

## 새 폴더의 AGENTS 역할

루트 AGENTS에는 **요구 근거, spec→구현→검증, 원본 보존, 공통 계약 담당, 실제 증거 기반 보고**만 짧게 쓴다. 추론 설정·프레임워크·폴더 규칙은 프로젝트에서 정한 것만 기록한다. 글로벌 지침을 복제하지 않는다.

폴더별 AGENTS가 요청되면 각 폴더에는 해당 역할만 둔다.

- `spec/AGENTS.md`: 필수 결과·동작·인수 조건을 관리한다. 업무 정책·공유 계약을 명확히 쓰고 중요한 선택에만 이유를 붙인다. 미정 동작을 완료로 표시하지 않는다.
- `src/AGENTS.md`: 확정된 spec을 최소 구현한다. 공통 계약을 재사용하고 관련 검증을 실행한다. 실행 DB·비밀·원본 데이터는 소스에 넣지 않는다.
- `docs/AGENTS.md`: 실행 방법·실제 검증 근거·중요 결정과 한계를 기록한다. 요구사항은 spec을 참조하고 원문 개인정보·비밀을 복사하지 않는다.
- `tests/AGENTS.md`: 인수 조건·독립 기대값을 확인한다. 사용자 DB 대신 격리한 자료를 쓰며 실제 브라우저와 DOM 검사의 차이를 기록한다.

## 창에 전달하는 작업

```text
이번 결과: [확정 spec과 인수 조건]
소유 파일: [정확한 경로]
읽을 계약과 선행 증거: [문서·검증 결과]
공통 파일 담당: [DB/앱등록/CSS/의존성/공유 상태 소유자]
검증: [실제 명령·대표 기대값]
인계: [완료·실패·계약 변경 요청을 남길 위치]
다른 작업자와 같은 코드베이스를 사용한다. 기존 변경을 되돌리지 말고,
담당 밖 수정이 필요하면 통합 담당자에게 요청한다.
```
