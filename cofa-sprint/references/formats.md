# 짧은 문서 양식

기존 프로젝트 양식이 있으면 재사용한다. 다음은 새 프로젝트 또는 사용자가 양식 단순화를 요청했을 때의 출발점이다. 빈 칸을 채우기 위해 문서·기능을 늘리지 않는다.

## spec00

```markdown
# 개발 지도
목표: [업무 결과와 성공 지표]
필수: [과제 원문 근거]
선택·제외: [모바일 / 외부 배포 / 실시간 / 최적화 등 큰 항목]
미정: [결과를 바꾸는 질문 또는 없음]
공통 보호 기준: [과제에 적용되는 권한·입력·비밀·보존 조건]

| spec | 사용자 결과·요구 ID | 선행 계약 | 담당 파일 | 완료 확인 | 모델·추론·fast | 상태 |
| --- | --- | --- | --- | --- | --- | --- |

병렬 가능: [작업 쌍과 조건, 공통 파일 통합 담당]
시간: [핵심 문제풀이 / 최소 서비스 / 통합 검증·제출 배분]
```

## 개별 spec

```markdown
# spec01 — [사용자 결과]
상태: 초안
근거: [README 요구 위치/ID]
결과: [무엇을 입력하고 무엇을 얻는가]
범위: [포함 / 제외]
중요 규칙과 이유: [판단이 갈리는 규칙만 짧게]
선행·담당: [의존 계약 / 담당 파일 / 공통 파일 소유자]
권장 모델·추론·fast: [과제 제한 안에서 모델·추론 + fast 켜기/끄기/유지 추천 + 한 줄 이유]

인수 조건:
- [ ] AC1 [상황·입력 → 관찰 가능한 결과]
- [ ] AC2 [중요 경계·권한·실패 → 결과]
공통 보호: [spec00의 해당 기준 참조]
검증: [실행 방법 / 실제 증거 문서]
직접 확인: [중요 결과 1~3개 또는 없음]
미정: [질문 또는 없음]
```

## 새 폴더의 AGENTS 역할

루트 AGENTS에는 **요구 근거, spec→구현→검증, 원본 보존, 공통 계약 담당, 실제 증거 기반 보고**만 짧게 쓴다. 추론 설정·프레임워크·폴더 규칙은 과제에서 정한 것만 기록한다. 글로벌 지침을 복제하지 않는다.

폴더별 AGENTS가 요청되면 각 폴더에는 해당 역할만 둔다.

- `spec/AGENTS.md`: 필수 결과·동작·인수 조건을 관리한다. 업무 정책·공유 계약을 명확히 쓰고 중요한 선택에만 이유를 붙인다. 미정 동작을 완료로 표시하지 않는다.
- `src/AGENTS.md`: 확정된 spec을 최소 구현한다. 공통 계약을 재사용하고 관련 검증을 실행한다. 실행 DB·비밀·원본 데이터는 소스에 넣지 않는다.
- `docs/AGENTS.md`: 실행 방법·실제 검증 근거·중요 결정과 한계를 기록한다. 요구사항은 spec을 참조하고 원문 개인정보·비밀을 복사하지 않는다.
- `tests/AGENTS.md`: 인수 조건·독립 기대값을 확인한다. 사용자 DB 대신 격리한 자료를 쓰며 실제 브라우저와 DOM 검사의 차이를 기록한다.

## 창에 전달하는 작업

```text
이번 결과: [확정 spec과 인수 조건]
소유 파일: [정확한 경로]
읽을 계약과 선행 증거: [문서·검증 결과]
공통 파일 담당: [DB/앱등록/CSS/의존성/공유 상태 소유자]
검증: [실제 명령·대표 기대값]
인계: [완료·실패·계약 변경 요청을 남길 위치]
다른 작업자와 같은 코드베이스를 사용한다. 기존 변경을 되돌리지 말고,
담당 밖 수정이 필요하면 통합 담당자에게 요청한다.
```
